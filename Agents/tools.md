# 개발 도구

루트 [AGENTS.md](../AGENTS.md)와 [공통 컨벤션](../Docs/Conventions/common.md)을 먼저 읽는다.

- 기존 `Tools/GameDataGenerator`와 실행 옵션을 확인하고 재사용한다. C++/Unity 전용 규칙을 C# 콘솔 도구에 그대로 강제하지 않는다.
- CLI 변경은 인자, 기본 경로, 출력, 종료 코드와 정상/오류 재현 방법을 함께 관리한다.
- 데이터 오류는 파일·시트·행·열 등 원인을 찾을 수 있는 위치를 표시한다.
- 입력 원본과 생성 출력을 구분하고 실패 시 원본·기존 출력 보호를 유지한다. 생성물을 수작업으로 고쳐 원본 문제를 숨기지 않는다.
- 새 도구는 기존 명령으로 해결하기 어려운 반복 수요가 있을 때만 만든다. 임의 패키지 설치나 외부 서비스 도입으로 범위를 확대하지 않는다.
- 변경 후 관련 기존 self-test와 필요한 빌드를 실행하고 미검증 항목을 남긴다.

- GameDataGenerator는 TextRPG에서 Client 전용으로 고정한다. 입력에 Server 대상 표·필드·열거형이 있으면 거부하고, Client C++ 타입·Enum 헤더와 실제 데이터 YAML을 결정적으로 생성한다. 실제 행 배열·정적 Find 함수·별도 schema YAML은 출력하지 않는다. 원본의 타입·필수·Enum·참조 검증과 두 출력 루트 보호는 유지한다. 기존 `--profile` 서버/레거시/Movement 선택 옵션을 다시 추가하지 않는다.
- GameDataPacker는 지정 루트의 `.yaml`을 하나의 AES-GCM 패키지로 묶는다. 게임 빌드는 반드시 `GameData/Data/Client`만 입력으로 삼아 exe 옆 `GameData.dat`를 만든다. 패키지 파일형식 버전과 YAML 데이터 프로토콜 버전은 별개이며 각 Client YAML의 `# TextRPG.GameData 1` 표식을 런타임에서 검사한다. 일반 YAML 전체가 아니라 생성기가 내보내는 mapping/scalar 형식만 지원하며 미지원 문법을 추정해 복구하지 않는다.
- 키 공급은 패커와 게임이 공유한다. `TEXT_RPG_GAMEDATA_KEY`가 정의돼 있으면 32바이트 키의 64자리 16진수만 허용하며 빈 값·잘못된 값에서 개발 키로 fallback하지 않는다. 변수가 없을 때만 현재 사용자 DPAPI로 보호한 `%LOCALAPPDATA%/TextRPG/Development/GameData.key`를 읽는 개발 편의를 제공한다. 빌드의 명시적 `prepare-development-key`가 최초 개발 키를 생성/재사용하며 게임 런타임은 생성하지 않는다. 손상된 기존 키 파일은 덮어쓰지 않는다. 이 개발 키는 동일 Windows 사용자용이며 제품 배포 키 전달 정책을 대신하지 않는다. 키 값 자체는 코드·문서·로그·명령행·dat에 기록하지 않는다. `verify`는 인증·복호화 후 엔트리 목록만 출력하고 평문 파일을 추출하지 않는다.
- 현지화 전용 Excel 검증(키 중복, 한국어·영어 필수값, 참조와 포맷 인자)은 별도 계약에 맞춰 구현하고, 진단에 통합문서·시트·행·열을 포함한다.
