# 다국어 문자열 및 Excel 관리 원칙

> 상태: TextRPG 콘텐츠·도구 작업에 적용할 설계 지침. 현재 런타임과 Generator는 Windows wide-string 기반으로 전환했지만 Excel 원본과 현지화 조회 경로는 아직 준비되지 않았다.

## 1. 제품 원칙과 적용 범위

플레이어에게 보이는 게임 내 모든 문구는 `GameData/Excel` 원본 데이터에서 관리한다. 한국어(`ko-KR`)와 영어(`en-US`)를 지원한다. 여기에는 메뉴 제목·버튼, 장면 이름, 대화·내레이션, 선택지, 캐릭터·몬스터·직업·아이템·맵 이름과 설명, 전투 메시지, 상태·도움말·게임 내 안내가 포함된다. 동적으로 표시되는 문구도 Excel의 번역 템플릿과 명시적인 인자 규칙을 사용한다.

유일한 게임 콘텐츠 예외는 비언어적 시각 표현이다. `GameData/Asset/Scene/*.txt`에는 ASCII 아트, 테두리, 비언어적 레이아웃만 둔다. 그림의 특정 위치에 렌더할 제목·레이블·버튼 문구는 Scene 데이터의 문자열 키로 지정하고 Excel에서 번역한다. ASCII 그림에 언어 문구를 그림 일부처럼 박아 넣어 예외 처리하지 않는다. 단, 언어 선택과 무관한 브랜드 표기 `TextRPG`는 메인 타이틀의 고정 워드마크로 사용할 수 있다.

게임 화면에 노출될 문구를 C++ 소스, Scene txt, 별도 JSON/CSV/INI 파일 또는 데이터 이름 필드에 직접 작성하지 않는다. 개발자 전용 진단 로그는 게임 콘텐츠와 구분하며 플레이어에게 보여서는 안 된다.

## 2. Excel 원본과 키 계약

현지화 데이터는 `GameData/Excel`의 단일 `Localization` 시트에 우선 모은다. 데이터가 커져 분리 필요성이 확인될 때만 도메인별 시트 분리를 검토한다. 권장 열은 다음과 같다.

| 열 | 용도 | 규칙 |
|---|---|---|
| `Key` | 언어와 무관한 문자열 식별자 | 필수, 전역 고유, 영문 대문자/숫자/밑줄 기반의 안정적인 이름 |
| `ko-KR` | 한국어 문구 | 필수, 비어 있지 않아야 함 |
| `en-US` | 영어 문구 | 필수, 비어 있지 않아야 함 |
| `Context` | 화면/상황/번역 메모 | 선택, 키의 의미와 길이·용어 제약 설명 |

예시 키는 `UI_MAIN_NEW_GAME`, `BATTLE_ACTION_ATTACK`, `MSG_BATTLE_VICTORY`처럼 용도를 드러내되, 키 자체에 한국어나 번역 문구를 넣지 않는다. 키는 기존 저장 데이터나 코드에서 참조될 수 있으므로, 뜻이 바뀌었다고 재사용하지 말고 필요하면 새 키를 만든다.

게임 규칙 표(예: Item, Job, Monster)의 화면 표시 필드는 문장을 담지 않고 `NameKey`, `DescriptionKey` 같은 문자열 키를 참조한다. 다른 문자열에 의존하는 동적 문장은 조각을 코드에서 붙이지 말고 번역 가능한 완전한 템플릿으로 정의한다. 포맷 인자 표기법과 허용 인자 타입은 Generator 계약에 명시하고 언어별 인자 누락·불일치를 검증한다.

## 3. Scene 및 화면 구성

Scene 식별자와 시각 레이아웃 정의는 게임 데이터로 관리하되, 렌더될 문구는 문자열 키로 연결한다. 예를 들어 MainMenu Scene은 배경 아트/정렬 정보를 보유하고 메뉴 항목은 각 언어 키를 사용한다. Battle Scene은 캐릭터 그림과 프레임을 유지하면서 `HP`, 전투 행동, 안내 문구 등의 표시 키를 Excel에서 가져온다. 숫자처럼 실행 중 변하는 값은 값과 현지화 문구를 분리해 렌더링한다.

현재 `MainMenu.txt`와 `Battle.txt`에는 ASCII 아트와 함께 영어 메뉴·상태·전투 문구가 들어 있다. 이를 새 계약에 맞게 분리하는 것은 후속 데이터/런타임 작업이며, 기존 txt를 바꾸려면 그에 맞춰 Scene 로더와 화면 구성이 함께 준비되어야 한다.

## 4. 언어 선택과 런타임 조회

런타임 언어는 하드코딩된 개별 문구 선택 분기가 아니라 `Language` 같은 명시적 언어 값으로 관리한다. 사용자가 설정한 언어를 한 세션의 일관된 렌더링 기준으로 삼으며, 텍스트 호출자는 문자열 키를 전달한다. 현지화 서비스가 선택 언어의 생성 데이터를 반환하도록 설계한다.

초기 기본 언어는 한국어(`ko-KR`)로 한다. 설정에서 영어(`en-US`)로 변경할 수 있고, 변경은 현재 화면부터 일관되게 반영한다. 설정 보존 위치는 설정 시스템 설계 시 정한다. 선택 언어 문구가 런타임에서 비정상적으로 누락되면 한국어로 fallback하고 개발 진단 로그에 키를 기록한다. 두 언어 중 한국어 원문까지 없는 키는 오류로 처리한다. 정상 릴리스의 `ko-KR`·`en-US` 누락은 Generator 검증 오류로 차단하며 fallback에 의존하지 않는다.

## 5. Generator 계약

기존 `Tools/GameDataGenerator`의 Excel 파싱, 일반 검증·위치 진단, 안전한 출력 교체 구조를 재사용한다. TextRPG Generator는 Client C++ 헤더와 YAML 데이터·스키마를 생성한다. 생성 문자열 필드는 Windows 런타임이 사용하는 `std::wstring`이며, 문자열 리터럴은 wide C++ 리터럴로 내보낸다. 서버·JSON·C# 산출 대상이나 `--profile` 선택 모드는 없다. 두 언어가 같은 생성 데이터에 포함되어야 하며, 언어별 빌드 옵션으로 문자열 내용을 바꾸지 않는다. YAML 패키지 포맷은 `006_YAML내보내기이식설계안.md`를 따른다.

Generator 검증은 최소한 문자열 키 중복, 필수 열과 값, 두 언어 번역 누락, 키 참조 존재 여부, 잘못된 포맷 인자, 줄바꿈·제어 문자 정책을 확인한다. 오류는 워크북·시트·행·열과 문제 키를 식별할 수 있어야 한다. 오류가 있으면 불완전한 새 산출물로 기존 정상을 덮어쓰지 않는다.

생성된 API의 구체 형태(열거형 키, typed ID, 테이블 컨테이너, `string_view` 수명 등)는 별도 C++ 산출물 설계에서 확정한다. 소스에서는 원시 문장 대신 생성 키를 사용하고 생성 코드는 손으로 편집하지 않는다.

## 6. 완료 기준과 현재 미완료 항목

향후 적용 작업은 아래를 만족해야 한다.

- 플레이어 노출 문자열이 Excel에서 한 곳의 키를 통해 관리된다.
- 두 언어 번역이 명시되고 화면의 현재 언어 선택과 조회 경로가 정해져 있다.
- Scene txt에는 ASCII 아트·비언어 레이아웃만 남고, 화면 문구는 Excel 키로 참조된다.
- 게임 데이터의 이름·설명 등 표시 필드는 번역 문자열 키를 참조한다.
- Generator가 두 언어 데이터를 검증하고 클라이언트 C++ 코드로 생성한다.
- 정상 데이터, 중복 키, 각 언어 번역 누락, 잘못된 참조의 진단과 생성 실패를 확인한다.

현재 런타임 프레임 버퍼와 Scene 경로는 `std::wstring`을 사용하고 `WriteConsoleOutputW`로 출력한다. Scene 로더는 비ASCII 바이트를 거부해 Scene 파일을 비언어 ASCII 아트로 제한한다. MainMenu ASCII 타이틀은 언어에 관계없이 `TextRPG`로 표시한다. Generator는 Client 전용 C++ 헤더와 `std::wstring` 필드를 생성하도록 수정했다. 다만 `GameData/Excel/Templates/GameDataTableTemplate.xlsx` 템플릿만 있고 현지화 데이터 workbook은 아직 없다. 기존 메뉴·전투 문구 이관, ko-KR/en-US 현지화 스키마 검증·런타임 조회, 번역 누락 검증은 미완료다. 이 전환의 빌드 결과는 별도 작업 기록에서 확인한다.
