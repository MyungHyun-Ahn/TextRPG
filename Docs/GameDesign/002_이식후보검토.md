# TextRPG 프로젝트 이식 후보 검토

> 상태: 이식 판단 기록. 초기 조사는 원본 코드를 복사하지 않고 재사용 후보를 분류했다. 후속 구현에서 아래 Generator 항목의 출력 계약을 Client 전용 C++ wide-string으로 전환했으며, 현재 상태는 §3·§5에 갱신한다.

## 1. 검토 범위와 기준

대상은 현재 TextRPG, 초기 TextRPG 초안, `OOP_TextShootingGame`, 현재 솔루션의 `GameDataGenerator`, 그리고 MMO_Portfolio에서 가져온 작업 지침이다. 판단은 다음처럼 나눈다.

- **유지**: 이미 프로젝트에 맞게 정리되어 있거나 그대로 참고할 일반 원칙
- **개념 재사용**: 책임과 흐름은 참고하되 TextRPG 요구에 맞게 다시 설계
- **부분 재설계**: 일부 알고리즘·데이터·콘텐츠만 검토 후 적용
- **가져오지 않음**: 현재 1차 목표와 무관하거나 의존성과 위험이 큰 영역

코드 파일이 있다는 사실만으로 구현 품질이나 빌드 성공을 의미하지 않는다. 이전 턴에 열린 ChatGPT 브라우저의 검토 답변은 소스 본문을 읽기 전에 파일명과 구조 설명만 전달해 받은 보조 의견이다. 아래 판정은 이후 `bangs read`로 확인한 실제 본문을 우선한다.

## 3. 확인된 데이터·장면 준비 상태

현재 `GameData/Asset/Scene`에는 `MainMenu.txt`, `Battle.txt`, `Town.txt`가 있다. MainMenu 브랜드 ASCII 타이틀은 언어와 관계없이 `TextRPG`로 통일했다. 위·아래 화살표 선택 후 Enter로 시작하면 Town ASCII Scene으로 전환한다. 장면 파일에는 ASCII 프레임·캐릭터 그림뿐 아니라 메뉴, 상태 레이블, 선택지 문구도 아직 남아 있다. 새 현지화 원칙에서는 이런 플레이어 노출 문구를 Excel 문자열 키로 옮기고 txt에는 ASCII 아트와 비언어적 화면 배치만 남겨야 한다. `GameData/Data`와 `GameData/Class`는 비어 있다. `GameData/Excel/Templates/GameDataTableTemplate.xlsx` 템플릿 파일은 있지만, 현지화 또는 게임 규칙 데이터를 담은 원본 workbook은 아직 확인되지 않았다.

Generator의 기본 Excel 입력은 `GameData/Excel`, 기본 생성 출력은 `Build/GameData/Generated`다. `GameData/Excel`에는 현재 `Templates/GameDataTableTemplate.xlsx`만 있으며 현지화 데이터를 입력한 원본 workbook은 없다. 컴파일 산출물 전용 `Out`과 게임 데이터 생성물 경로를 섞지 않는다. 새 현지화 시트와 키/번역 규칙을 먼저 정하고, C++ 결과물의 파일 배치·타입·참조·접근 방식을 확정해야 한다. 기존 Scene 문구의 데이터 이관과 Generator 연결은 아직 수행하지 않았다.

## 4. 이식 판단 요약

- **그대로 복사할 C++ 구현:** 현재 확인된 자료 중 승인할 항목 없음.
- **기획으로 유지:** 초기 TextRPG의 직업·장소 이동·몬스터 조우·전투 흐름. 범위와 규칙은 별도 확정한다.
- **개념을 가져와 재설계:** Scene 생명 주기, 객체의 갱신/렌더 역할, 화면 그리기 경계, 입력→업데이트→렌더 조정, 텍스트 파일 로딩·검증.
- **Generator 현재 전환:** Excel 파싱, 일반 검증/진단, 안전한 출력 교체, `--check`를 유지하면서 Client 전용 C++ wide-string 헤더를 생성한다. 현지화 시트 전용 검사와 키 조회 API는 별도 구현이 필요하다.
- **정책으로 유지:** 현재 TextRPG에 맞게 정리된 C++ 규칙, 소유권·원본 데이터 보호·변경 범위·검증 원칙.
- **가져오지 않음:** 슈팅 게임 전용 탄환/충돌/실시간 이동/FPS/전역 싱글턴 구조와 MMO 서버·네트워크·DB·저장소 운영 체계.

## 5. 구현 전 남은 결정

1. Scene txt 문법, 인코딩, ID와 선택지/전환 표현, 오류 위치 보고
2. `IScene`, `IObject`의 최소 책임과 Scene별 객체 소유권, 안전한 전환 시점
3. 메모리 이중 프레임 버퍼와 콘솔 출력 백엔드의 계약, 한글 폭·콘솔 크기 변경 처리
4. Localization Excel의 실제 열·키·번역 검증과 생성 데이터의 문자열 조회 API
5. 기존 ShootingGame의 화면 자료 중 실제로 RPG 콘텐츠로 쓸 항목
6. Unicode 출력에서 full-width 문자·줄 경계·surrogate pair의 셀 폭 처리 및 콘솔 크기 변경 동작. 최신 C++/C# 빌드는 Debug/Release × x86/x64에서 통과했으며, Generator self-test와 실제 콘솔 실행은 이번 변경에서 실행하지 않았다.

## 6. 다음 검토 단계

설계 문서 `001_GameDesign.md`와 이 검토를 기준으로 Excel 현지화 원본 → C++ wide-string 조회 → Scene 표시의 작은 수직 슬라이스를 이어간다. 이 문서는 이식 판단의 배경과 구현 후 상태를 기록하며 별도 코드 이식 승인을 의미하지 않는다.
